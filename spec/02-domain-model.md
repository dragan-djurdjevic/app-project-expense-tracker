# 02 — Domain model

All entities share the common fields in DM-000. Field tables list: name (TS / DB), type, required, rules.

## DM-000 Common fields
| Field (TS / DB) | Type | Rule |
|---|---|---|
| `id` / `id` | UUID string | generated by `IdGenerator`, immutable |
| `createdAt` / `created_at` | ISO timestamp UTC | set on create from `Clock`, immutable |
| `updatedAt` / `updated_at` | ISO timestamp UTC | set on create and every update/archive/restore |
| `archivedAt` / `archived_at` | ISO timestamp UTC or null | null = active; set by archive, cleared by restore |

## DM-001 Value objects
- **Money** — integer minor units, `0 ≤ value ≤ 999 999 999 999` (BR-GEN-001). Negative amounts not allowed.
- **VatRate** — integer basis points, `0 ≤ rate ≤ 10000` (0 %–100 %).
- **DateOnly** — ISO `YYYY-MM-DD`, must be a valid calendar date.
- **VatNumber** — trimmed string, 3–20 chars, letters/digits/`-` only, stored upper-case.
- **Email** — optional; when present must match a basic `x@y.z` pattern.
- **Text fields** are trimmed; empty string after trim is treated as null for optional fields.
- **Errors:** invalid Money → `BR-GEN-001` (`errors.money.invalid`); invalid VatRate, DateOnly, VatNumber or Email
  format → `BR-GEN-003` (`errors.format`); empty required value (e.g. DateOnly `""`) → `BR-GEN-002`
  (`errors.required`).

## DM-050 Invoice
| Field | Type | Req | Rules |
|---|---|---|---|
| number / number | string 1–50 | ✔ | unique per contract (BR-IVC-003) |
| contractId / contract_id | UUID → Contract | ✔ | immutable after create; BR-IVC-001 |
| value / value | Money (net) | ✔ | |
| vatRate / vat_rate | VatRate | ✔ | default = settings.default_vat_rate |
| date / date | DateOnly | ✔ | issue date; determines year for "collected"/"paid" in analytics |
| dueDate / due_date | DateOnly | | must be ≥ date (BR-IVC-004) |
| status / status | InvoiceStatus | ✔ | default `DRAFT`; on create may be `DRAFT`, `ISSUED` or `CANCELLED` (reachable from DRAFT); BR-IVC-005 |
| description / description | string ≤1000 | | |
| attachment / attachment_path, attachment_name | StoredDocumentRef or null | | PDF only, ≤ 20 MB (BR-IVC-006) |

Derived (never stored): `vatAmount = round_half_up(value × vatRate / 10000)`, `gross = value + vatAmount`.

**InvoiceStatus** enum: `DRAFT`, `ISSUED`, `PAID`, `CANCELLED`.
Direction of an invoice = type of its contract (INCOMING invoice → money in; OUTGOING → money out).

Archived invoices (BR-GEN-007): `changeStatus`, `attachDocument` and `removeDocument` on an archived invoice return
BR-GEN-007; `openDocument` is allowed. "Overdue" (UI-050) compares `dueDate` with the local calendar date of `Clock.now()`.

Invoice input defaults: on create, an omitted or null `vatRate` = settings.defaultVatRate and an omitted `status` =
DRAFT; on `update`, an omitted or null `vatRate` / omitted `status` keeps the stored value. `contractId` is not
re-checked on `update` (it is immutable, BR-IVC-002): per BR-GEN-006 an invoice stays editable after its contract
or project is archived.

Document operations: `removeDocument` on an invoice without an attachment is a no-op success; `openDocument` on an
invoice without an attachment is a programming error (throws, AR-005).

**StoredDocumentRef** = `{ path: string /* relative to storage root */, originalName: string }`.

## DM-060 Settings (single row)
| Field | Type | Default |
|---|---|---|
| currency / currency | ISO 4217 code, one of `EUR`, `RSD`, `USD`, `CHF`, `GBP` (else `BR-GEN-003` `errors.format`) | `EUR` |
| defaultVatRate / default_vat_rate | VatRate | `2000` |
| language / language | one of `en`, `sr-Latn` (else `BR-GEN-003` `errors.format`, field `language`) | `en` |

Settings are editable on the Settings screen (UI-080). Changing currency only changes display; amounts are not converted.
Changing language only changes the UI language and formatting (UI-002, UI-090); stored data is not changed.

## Business rules
| ID | Rule | Error messageKey |
|---|---|---|
| BR-GEN-001 | Money values must be integers 0…999 999 999 999 | `errors.money.invalid` |
| BR-GEN-002 | Required fields must be present and non-empty after trim | `errors.required` |
| BR-GEN-003 | String lengths and formats per field tables | `errors.format` |
| BR-GEN-004 | Archive sets `archivedAt`; restore clears it. Archiving an already archived record is a no-op success. Restoring an active record is a no-op success. | — |
| BR-GEN-005 | Archiving a parent does **not** archive its children. | — |
| BR-GEN-006 | A new or updated record may not reference an **archived** parent. Existing references to a parent archived later stay valid. | `errors.parentArchived` |
| BR-GEN-007 | Archived records are read-only in the UI except for **Restore**. Use cases reject `update` on archived records. | `errors.archivedReadOnly` |
| BR-GEN-008 | Restoring a child whose parent is archived is allowed (the record remains consistent). | — |
| BR-INV-001 | Investor VAT number unique among investors | `errors.vat.duplicate` |
| BR-SUB-001 | Subcontractor VAT number unique among subcontractors | `errors.vat.duplicate` |
| BR-PRJ-001 | `investorId` must reference an existing investor (active, per BR-GEN-006) | `errors.parentArchived` / `errors.notFound` |
| BR-CON-001 | `projectId` must reference an existing project (active, per BR-GEN-006). Unknown → `{code:"BR-CON-001", field:"projectId", messageKey:"errors.notFound"}`; archived → `{code:"BR-GEN-006", field:"projectId", messageKey:"errors.parentArchived"}` | `errors.parentArchived` / `errors.notFound` |
| BR-CON-002 | `OUTGOING` ⇒ `subcontractorId` required and must reference an existing subcontractor (active, per BR-GEN-006). Field `subcontractorId`. Missing → code `BR-CON-002`, `errors.contract.subcontractorRequired`; unknown → code `BR-CON-002`, `errors.notFound`; archived → code `BR-GEN-006`, `errors.parentArchived`. On update the reference is re-checked only when `subcontractorId` changes. | `errors.contract.subcontractorRequired` / `errors.notFound` / `errors.parentArchived` |
| BR-CON-003 | `INCOMING` ⇒ `subcontractorId` must be null. Field `subcontractorId`. | `errors.contract.subcontractorForbidden` |
| BR-CON-004 | `number` unique within the same project (incl. archived contracts), case-insensitive (ASCII, as `COLLATE NOCASE`, AR-004). Field `number`. | `errors.contract.numberDuplicate` |
| BR-CON-005 | `type` and `projectId` cannot change after create. Update input has the same shape as create; field = the first changed one in order `type`, `projectId`. | `errors.immutable` |
| BR-IVC-001 | `contractId` must reference an existing contract (active, per BR-GEN-006). Field `contractId`. | `errors.parentArchived` / `errors.notFound` |
| BR-IVC-002 | `contractId` cannot change after create. Field `contractId`. | `errors.immutable` |
| BR-IVC-003 | `number` unique within the same contract (incl. archived), case-insensitive (ASCII, as `COLLATE NOCASE`, AR-004). Field `number`. | `errors.invoice.numberDuplicate` |
| BR-IVC-004 | `dueDate`, if set, ≥ `date`. Field `dueDate`. | `errors.invoice.dueBeforeDate` |
| BR-IVC-005 | Status transitions allowed: DRAFT→ISSUED, DRAFT→CANCELLED, ISSUED→PAID, ISSUED→CANCELLED, ISSUED→DRAFT, PAID→ISSUED (undo). CANCELLED is final. Same-status "transition" (incl. CANCELLED→CANCELLED) is a no-op success (record and `updatedAt` unchanged). On create, `status` defaults to DRAFT and may be DRAFT, ISSUED or CANCELLED; anything else fails. On `update` and `changeStatus(id, status)`, a changed status must be an allowed transition from the stored status. Error `{code:"BR-IVC-005", field:"status"}`. | `errors.invoice.statusTransition` |
| BR-IVC-006 | Attachment must be a PDF (file starts with `%PDF-` bytes **and** extension `.pdf`, case-insensitive) and ≤ 20 MB (20 × 1024 × 1024 = 20 971 520 bytes). Checked in order: PDF (extension and magic bytes) → `notPdf`, then size → `tooLarge`. Error `{code:"BR-IVC-006", field:"attachment"}`. | `errors.attachment.notPdf` / `errors.attachment.tooLarge` |
| BR-IVC-007 | Replacing an attachment removes the previous stored file; removing an attachment deletes the stored file and clears the fields. Archiving an invoice keeps its file. | — |
| BR-IVC-008 | Sum of non-cancelled invoice values (archived invoices included) on a contract **may** exceed the contract value; the UI shows a warning (UI-052), not an error. `createInvoice`/`updateInvoice` then return the warning `"overInvoiced"` (AR-005): set when, after the save, Σ values of non-cancelled invoices on the contract (archived invoices and this invoice included) > contract value. | — |
