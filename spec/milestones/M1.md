# M1 — Initial app setup

## Scope (spec IDs)
OV-003, AR-001 … AR-011 (incl. AR-006a), DS-001 … DS-005, DM-000, DM-001, DM-060, UI-001, UI-002, UI-080, UI-090.
DM-010 … DM-050 and AN-1 … AN-5: TypeScript types only (needed by the port interfaces of deliverable 3).

## Deliverables
1. Tauri 2 + React + TS + Vite project scaffolded per AR-006/AR-007 (app identifier `com.archtracker.app`,
   product name "Architecture Project Tracker", version `0.1.0` in both `package.json` and `tauri.conf.json`).
2. ESLint flat config with `eslint-plugin-boundaries` enforcing AR-002; Prettier config.
3. Core: `Result`, `DomainError`, value objects `Money`, `VatRate`, `DateOnly`, `VatNumber`, `Email` (DM-001);
   ports from AR-004 (interfaces only for entity repositories and AnalyticsQuery; they are implemented in M2–M5);
   `Clock`, `IdGenerator`; settings use cases `getSettings`, `updateSettings`.
4. Adapters: `SqlDriver` + `TauriSqlDriver` + `SqlJsDriver`; migration runner; `0001_init.sql` exactly as DS-003;
   `SqliteSettingsRepository`; `FsDocumentStorage` + `InMemoryDocumentStorage`; `SystemClock`, `UuidIdGenerator`.
5. Composition root with Tauri/browser mode detection (AR-009) and startup sequence (AR-010).
6. App shell with sidebar (UI-001); every entity/analytics route shows a placeholder "Coming in Mx" except
   Settings (UI-080), which is fully functional.
7. i18n set up with `en.json` (UI-090).
8. Formatting helpers (UI-002): `formatMoney`, `parseMoney`, `formatPercent`, `formatDate`, `parseVatPercent`.
9. package scripts from AR-011, `.yarnrc.yml` and `packageManager` field (AR-006), including `scripts/trace.mjs`, `scripts/check-env.mjs`, `scripts/smoke-mac.mjs`.
9a. `.nvmrc` (`22`), `engines.node`, `src-tauri/rust-toolchain.toml` (AR-006); data dir override +
    `get_data_dir` command (AR-009).
10. Playwright config running against the `e2e` browser build.
11. GitHub Actions workflow `.github/workflows/windows-build.yml` on `windows-latest`, triggered by `push` to `main` only,
    `pull_request` (any target) and `workflow_dispatch` (one run per PR update): `corepack enable`, `yarn install --immutable`, `yarn test`,
    `yarn build`, upload the NSIS installer as an artifact, then the Windows installer smoke test (TC-M1-032).
12. `README.md`: prerequisites from AR-012 (nvm/Node 22, rustup via Homebrew, Xcode CLT, cross-build tools; WebView2
    on Windows) and how to run dev/test/verify/build.

## Acceptance criteria
- `yarn verify` passes locally on macOS (tests + macOS app smoke + Windows installer cross-build).
- After the user allows a push: Windows CI produces `Architecture Project Tracker_<version>_x64-setup.exe` and passes
  TC-M1-032. Until then the milestone may be closed as PASS-WITH-PENDING.
- No file in `src/core` imports anything outside `src/core`.
